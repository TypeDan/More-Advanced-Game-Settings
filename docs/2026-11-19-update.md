# Version 2026.11.19.1 — published 19 November 2026

Shared fixes prepared in this project and Yuletide Raids:

- Read the separate military-handicap section from the actual lobby descriptor.
- Resolve per-player economy, military and population settings with the native lobby-slot API.
- Apply handicaps after player/starting-age initialization.
- Apply explicitly configured maximum population through the engine override at match start, so an earlier modifier cannot be masked by a native cap override.
- Keep the optional defeated-teammate population transfer effective when an explicit cap override is active.
- Add small, non-interactive local-player text with no background or border just above the bottom-left resource box, with Eco, Military and Pop stacked vertically. Configured-but-unapplied boosts and cap mismatches are amber. Hide it for players with no custom settings, eliminated players and replays. The shared HUD was checked live in Yuletide at 1920 x 1080, directly above the bottom-left resource box.

`tests/test_player_settings.py` exercises the actual UI descriptor and Lua code for player 1 at 250 population, player 2 at double economy, all eight slots with simultaneous economy/military/cap settings, reversed internal order, default/global caps and population transfers. `tests/test_bonus_hud.py` exercises the real application functions before displaying bonuses, local-player isolation, cap mismatch/transfer updates, hide/restore handling and XAML syntax. Both pass using engine stubs. The shared code was also exercised in a native Yuletide match: human host in lobby slot 1 had a 250 maximum population and no economy/military bonuses; slot 2 had 200 population, economy multiplier 1.2 and military multiplier 1.5, matching the separate +20%/+50% lobby settings. Internal player iteration order was reversed. The game HUD showed 7/250 and the small Pop 250 status line.
